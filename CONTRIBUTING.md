# Contributing to FFM Sentinel

Thank you for your interest in improving FFM Sentinel.

## Before you start

1. Check existing issues and pull requests to avoid duplicating work.
2. For a significant change, open an issue or discuss the proposal with the maintainers first.
3. Keep contributions relevant to the project's goal: an interactive, locally oriented multimodal AI companion.

## Workflow

1. Fork the repository or create a feature branch.
2. Make focused, clearly scoped changes.
3. Follow the existing style and keep code readable.
4. Never commit passwords, API keys, access tokens, private data, or local configuration files.
5. Test the changed behaviour on your available environment and describe what you could and could not test.
6. Update documentation when setup steps, commands, dependencies, or behaviour change.
7. Open a pull request with a clear summary, motivation, test steps, and screenshots/logs where useful.

## Commit messages

Use short, descriptive messages, for example:

- `docs: clarify local setup`
- `fix: handle missing model response`
- `feat: add supported input option`
- `test: cover configuration validation`

## Hardware and AI integrations

- Do not claim a feature works unless it has been implemented and tested.
- Clearly identify hardware/model requirements and known limitations.
- Do not include fabricated benchmark results or test evidence.
- Check third-party model and dependency licenses before redistributing them.

## Code of conduct

Be respectful, constructive, and welcoming. Focus feedback on the work, not the person. Harassment, discrimination, and deliberately disruptive behaviour are not acceptable.
